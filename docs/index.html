    Data discoverability · open source

    Find UK public sector data and check its metadata, from your AI assistant

    NDL PubSec MCP helps people and AI assistants find UK public sector data, the standards that apply to it, and how it moves between organisations. It is an open-source MCP server for the National Data Library: it searches data.gov.uk, checks metadata against the cross-government model (xGov MEM) and explains the rules, all read-only.

    New

    This page is about how the UK public sector finds, describes and shares data, and a small open-source tool that helps AI assistants do the same. You do not need to install anything or know any technical terms to use this page.

    In one minute

    NDL stands for the National Data Library, the government's programme to make public sector data easier to find and use. PubSec means public sector. MCP is a way to plug tools into AI assistants.

    Public bodies publish thousands of datasets and run hundreds of systems that pass data between them. It is hard to know what exists, what it means, who may use it and which rules apply. This project gathers that knowledge in one place, for people on this page and for AI assistants through a small set of read-only tools.

    It is an independent prototype: it is not a government service and it never changes or shares anyone's data.

    What it does

    Updated

    Each tool does one job. Filter them by what you want to do.

    catalogue_search

    Search data.gov.uk

    Search the data.gov.uk catalogue of UK public sector datasets. Returns titles, publishers, licences, formats, last-modified dates and links. Read-only; no personal data is returned.

    • Find data
    • Uses the live catalogue
    • Read-only
    Inputs
    • query (required): What to look for, in plain words, for example 'school census' or 'flood risk'
    • organisation: Optional publisher slug from data.gov.uk, for example 'department-for-education'
    • limit: How many results to return (1 to 20)
    • offset: How many results to skip, for paging

    dataset_describe

    Describe a dataset and check it against xGov MEM

    Get one data.gov.uk dataset: its description, publisher, licence and distributions, plus a draft UK Cross-Government Metadata Exchange Model (xGov MEM) record and what that record still lacks. Nothing is guessed: fields the catalogue does not hold are reported as missing.

    • Find data
    • Uses the live catalogue
    • Read-only
    Inputs
    • id (required): The dataset id or name (slug) from data.gov.uk

    metadata_validate

    Validate metadata against xGov MEM

    Check a metadata record against the UK Cross-Government Metadata Exchange Model (xGov MEM, commit d6d9a24). Classes: ContactPoint, DataService, Dataset, Distribution, Organisation. Returns errors (must fix) and warnings (recommended), each with the attribute path.

    • Check metadata
    • Works offline
    • Read-only
    Inputs
    • record (required): The metadata record as a JSON object, using xGov MEM attribute names (up to 100 KB)
    • className: Which xGov MEM class to validate against. If left out, it is read from the record's type, for example dcat:Dataset

    standard_explain

    Explain an open data standard

    Explain the open standards recommended or required across UK government and the wider public sector, for data, APIs, identifiers, cyber security, digital services, identity, health and procurement: purpose, how firmly it applies, who it applies to, status, licence and link, each with its provenance label and check date. Leave id out to list them all, optionally for one domain.

    • Explain
    • Works offline
    • Read-only
    Inputs
    • id: Standard id, for example 'xgov-mem', 'dcat' or 'bods'. Leave out to list all
    • domain: List only the standards in this domain, for example 'Cyber security'

    term_lookup

    Look up a business term and whether it is certified

    Find business terms in the configured vocabulary and report, for each, its definition, its status, who drafted it (person or AI), the review level it passed (H0 to H5) and whether that makes it certified. A term counts as certified only when it is endorsed after H2 review or above; anything unrecorded is reported as unknown, never assumed. Leave query and id out for a summary of the vocabulary.

    • Explain
    • Works offline
    • Read-only
    Inputs
    • query: Words to look for in term labels, alternative labels and definitions
    • id: An exact term id, for example 'NDL-GLO-007'
    • limit: How many terms to return (1 to 25)

    domain_list

    List the MCP servers in this estate

    List the MCP servers that work alongside this one (for example the Public Sector Data Quality Commons), with what each is for, its tools, its safety statement and where its manifest came from. This server does not call them.

    • Connect
    • Works offline
    • Read-only

    api_search

    Find UK public sector APIs

    Search UK public sector APIs by words in their name, provider or description, optionally for one provider. Draws on the UK public sector API catalogue at a pinned commit, plus APIs added by name after checking them at the publisher's page (each says which). Returns name, provider, description, endpoint and documentation links, and the source of each entry. Read-only: this server lists APIs and never calls them, holds no keys and passes no data. Listing is not endorsement, and using an API may need its own sign-up or a legal basis.

    • Find data
    • Works offline
    • Read-only
    Inputs
    • query (required): Words to look for, for example 'VAT number', 'trade statistics' or 'EORI'
    • provider: Optional provider name or id, for example 'HM Revenue & Customs' or 'hm-revenue-customs'
    • limit: How many APIs to return (1 to 25)

    server_search

    Find MCP servers for UK public sector work

    List or search MCP servers an agent might use alongside this one: the estate's own servers (with their manifests or repositories) and public candidates awaiting the owner's review. Each entry says its status, where it was checked and when. Candidates are not endorsed. This server never calls any of them.

    • Connect
    • Works offline
    • Read-only
    Inputs
    • query: Words to look for in a server's name or description; leave out to list all

    exchange_search

    Find data exchanges between public sector organisations

    Find data exchanges between UK public sector organisations by journey (for example 'register a death', 'claim universal credit', 'set up a limited company'), organisation or identifier. Each result gives the parties, what flows, how, the shared identifiers, the standards involved, the legal basis where known, suggested api_search queries and sources with a provenance label. Also returns counts from the Digital Economy Act register of information sharing agreements. Descriptive only: this server never takes part in an exchange.

    • Find data
    • Works offline
    • Read-only
    Inputs
    • query: Words for a journey, organisation, data item or identifier; leave out to list all
    • party: Only exchanges involving this organisation, for example 'HMRC'
    • audience: Only journeys for this audience

    Check a record

    Paste a metadata record as JSON and check it against xGov MEM. This runs the server's own validator in your browser, compiled from the same model. Nothing you paste is sent anywhere or kept.

    How well it follows xGov MEM

    The validator is generated from the xGov MEM model at commit d6d9a24 (1 June 2026). It covers 5 classes.

    It reaches the same verdict as the model's own tests on 32 of 32 cases: 12 valid and 20 invalid examples.

    • Valid examples accepted
    • Invalid examples rejected
    Agreement with the xGov MEM test corpus, by class
    ClassValid examples acceptedInvalid examples rejected
    ContactPoint1 of 12 of 2
    DataService5 of 59 of 9
    Dataset2 of 25 of 5
    Distribution4 of 44 of 4

    50 real data.gov.uk records were mapped (a crosswalk) and checked by this server and by the model's own LinkML validator: 50 of 50 agree. None is valid straight from the catalogue. These are the required attributes the catalogue records lack.

    The corpus is small, and some examples break more than one rule. The real-record sample is 50 records, not the whole catalogue. Agreement means the same verdict and the same missing attributes, not identical messages.

    Exchanges and journeys

    New

    When you register a death, claim a benefit or set up a company, data often moves between organisations behind the scenes. Here are 18 of those data exchanges, the journey each one serves, who is involved, what moves and how, the identifiers that join the data, and the law that allows it.

    667information sharing agreements on the Digital Economy Act register, read 20 November 2026; 194 are still active
    11record an API as their method (6 of the active ones). Most record secure file transfer, a shared platform or encrypted email
    326are about fuel poverty: the largest single purpose

    What these numbers do and do not show

    Each agreement records exactly one 'information sharing method'. It is the main method declared for the agreement, not every route used: agreements 205, 284 and 663 (the Warm Home Discount helpline, 2022 to 2027) record trusted partner transfer, encrypted hardware or secure file transfer, yet their disclosed-information text says electronic access to DWP's Citizen Application Programming Interface (CAPI) will also be enabled. So API counts from this field are a floor.

    The register counts agreements, not how much data moves. Much cross-government sharing runs over APIs it does not show:

    • DWP reported demand for its data from other government departments rising from 4.5 million to over 7.5 million API requests a day at peak, all routed through its API gateway (How APIs kept our country running when everything stopped (DWP Digital blog, 8 December 2021); S: Found through search; re-verify).
    • DWP's Citizen API gives other government departments and approved external agencies access to DWP citizen information (Citizen API on the UK government API catalogue; S: Found through search; re-verify).
    • The government API catalogue lists 48 DWP APIs, including Get Citizen Income Information, View Earnings, Citizen Address and the FINDr Matching Service, added on 23 April 2024 (co-cddo/api-catalogue, data/catalogue-from-json-source.csv at b239f15; V: Verified at the primary source).

    So the finding is about the register, not about government as a whole: its single method field cannot say which agreements also use APIs, which is itself a gap worth fixing.

    Safeguards for AI use

    New

    For companies building AI models, assistants and MCP servers, and for anyone deciding whether to trust what an assistant tells them, this is a ready-made, read-only way to reach UK government data resources, with the safeguards built in rather than promised.

    Read-only, always

    Every tool is marked read-only and non-destructive, and a test fails if one is not. It never changes, adds or deletes anything, logs in anywhere or holds keys.

    No personal data

    It reads published, public sources only. The registers it compiles drop contact details, and the build refuses to publish if an email address survives.

    Checked inputs

    Every input has a length limit, and free-text fields that name organisations accept only letters, numbers and a few punctuation marks, so odd input is refused rather than passed on.

    Fixed, secure sources

    It reads data.gov.uk over https only, and gives up after 15 seconds. It never calls the APIs or MCP servers it lists, and never takes part in the data exchanges it describes.

    Sources and provenance on every answer

    Each result names its source and a provenance label (verified, found through search, background knowledge or unconfirmed) with the date it was checked. Pinned data carries its date, and the build fails once the API catalogue copy is 100 days old.

    Prompts that keep assistants honest

    Its ready-made prompts tell the assistant to cite what the tools returned and not to claim anything they did not return.

    Open and scanned

    The code is open source and checked on every change by tests, CodeQL code scanning, dependency review and the OpenSSF Scorecard, with workflow actions pinned to exact versions.

    Nothing leaves this page

    This page makes no network requests: search and ask run in your browser, under a strict content security policy.

    What it does not do

    • It does not reach restricted or personal data. Data held about named people or businesses needs a legal gateway and an agreement; the exchanges section shows where those exist.
    • It does not make an AI assistant infallible. Assistants can still misread results, so check the source named with each one.
    • It is not a government service and does not replace the official catalogues, registers or the coming National Data Library services.

    Building with it: connect it to your assistant (How to use it), read the machine description in llms.txt, or harvest the knowledge graph. Report a safety concern through the private security form.

    Getting started

    Do I need to be technical to use this page?

    No. Start with New here? Start here, use Search or ask, and hover over dotted words for their meaning. Only connecting the server to an AI assistant needs some set-up.

    Is there a chatbot?

    Yes, in two ways. On this page, Search or ask (press /) finds the passages that answer your question and can turn them into a prompt for your own AI assistant; no AI runs on the page itself. And any AI assistant that supports MCP can use this server's tools and ready-made prompts directly.

    Why was this project started?

    Because people who need government data, and the AI assistants they use, cannot easily tell what data exists, who publishes it, or whether its description is good enough to rely on. It tests, with working software rather than slides, what a machine-friendly front door to that data needs.

    What does NDL stand for?

    The National Data Library: the UK government's programme, led by DSIT with GDS, to make public sector data easier to find and use. Since early 2026 data.gov.uk has been turning into it. PubSec means public sector, and MCP is the Model Context Protocol, a way to plug tools into AI assistants.

    Do I need to install anything to try it?

    No. The record checker on this page runs the server's own validator in your browser. To use the tools from an assistant, you need to install the server.

    What do I need to install it?

    Node.js 20 or later, git, and an assistant that supports MCP, such as Claude Desktop or VS Code.

    Which assistants work?

    Any assistant that can start an MCP server over stdio. Snippets are given for Claude Desktop and VS Code; others follow the same pattern.

    Using the tools

    How do I choose a tool?

    You usually do not: ask your question and the assistant picks. To be sure, name the tool in your prompt, for example 'use metadata_validate'.

    Can I check many records at once?

    Each call checks one record. Ask the assistant to go through a list and give you a table, then check the totals yourself.

    Why do I see at most 100 findings?

    Findings are capped at 100 per call, with a count of how many were left out, so one very broken record cannot flood the reply (defect D-020).

    Can I point it at a different catalogue or vocabulary?

    Yes. NDL_MCP_CKAN_BASE sets the catalogue API (https only) and NDL_MCP_VOCAB_PATH sets the vocabulary term_lookup reads. See the README for details.

    Does it call the APIs it finds?

    No. api_search and server_search list APIs and servers with where each entry came from; this server never calls them, holds no keys and passes no data.

    Trust and safety

    Does it change anything?

    No. Every tool is read-only. It never writes to a catalogue, sends messages or stores what you ask.

    Does it handle personal data?

    No personal data is read or returned. Do not paste personal data into the checker or your prompts.

    Can I rely on the answers?

    Results come from the sources named with them, but the assistant can still make mistakes. Check the source before you rely on a result, and treat provenance labels S, K and U as leads, not facts.

    Is this a government service?

    No. It is an independent prototype. It is not endorsed by any government department and does not set policy.

    Troubleshooting

    The assistant does not show the tools

    Check the path in the settings points at dist/index.js, that npm run build finished, and restart the assistant. Then try npm run inspector.

    Search returns nothing or fails

    The catalogue may be unreachable. A weekly live smoke test watches for changes to its API; check the open items, then raise it through the contact form.

    The checker says my record is invalid, but I think it is right

    Check the class is right and attribute names are spelt as the model spells them (UK spelling, for example licence). If you still disagree, tell us: it may be a difference from the standard.

    AI assistant
    A chat tool such as Claude, ChatGPT or Copilot that answers questions in everyday language. With an MCP server plugged in, it can look things up in sources it could not reach on its own.
    API
    Application programming interface: a way for one computer system to ask another for data or to do something, without a person in between. Many government services offer APIs alongside their websites.
    API catalogue
    A list of APIs with what each does, who provides it and where its documentation is. The UK public sector API catalogue is at api.gov.uk; api_search reads it at a pinned commit.
    CKAN
    The open-source catalogue software behind data.gov.uk. Its "action API" is what this server calls.
    Class
    A kind of thing in xGov MEM, for example Dataset or DataService.
    Co-design
    Designing a service with the people who will use it, not only for them: they shape the personas, journeys and changes.
    Crosswalk
    A mapping from one metadata format to another; here, from a data.gov.uk entry to xGov MEM.
    CURIE
    A short form of a web address, written prefix:name. For example, dcat:Dataset.
    DAM policy
    The cross-government policy on critical data assets (the successor to the Essential Shared Data Asset policy), with returns to GDS from January 2027.
    Data champion
    Someone who promotes good data practice in their own organisation, often alongside their main job.
    Data exchange
    Data passing from one organisation to another for a stated purpose, such as payroll earnings going from HMRC to DWP so Universal Credit can be worked out.
    Data service
    In DCAT, a set of operations, such as an API, that gives access to datasets or data processing. DCAT-AP-UK describes APIs this way, so they can be catalogued like datasets.
    data.gov.uk
    The UK's national catalogue of public sector data.
    DCAT
    Data Catalog Vocabulary, the W3C standard for describing datasets in catalogues. xGov MEM builds on it.
    Distribution
    One available form of a dataset, such as a CSV file or an API.
    Finding
    One problem the validator reports, with a severity, a path and a message.
    Information sharing agreement
    A written agreement between organisations setting out what personal data they share, why, how, for how long and under which law. Agreements under the Digital Economy Act 2017 are listed on a public register.
    Legal gateway
    The law that allows one public body to share data with another for a particular purpose. Without one, a body may not be allowed to share, even when sharing would help.
    LinkML
    The modelling language xGov MEM is written in.
    MCP
    Model Context Protocol: an open standard for connecting AI assistants to tools and data.
    MCP prompt
    A ready-made task an MCP server offers to an AI assistant, such as 'map the data exchanges behind a journey'. It is text that asks the assistant to use the tools; it does not act by itself.
    MCP server
    A program that offers tools and resources to an AI assistant using MCP. This repository is one.
    Metadata
    Data about data: the title, description, publisher, licence, dates and format that tell you what a dataset is and whether you can use it.
    National Data Library
    The UK government's programme, led by DSIT with GDS, to make public sector data easier to find and use. Since early 2026 the data.gov.uk website has been turning into it. The NDL in this project's name.
    Open standard
    A published, openly available specification that anyone can use, so that different systems and organisations can work together without being tied to one supplier.
    Persona
    A short description of a type of user: their context, goals and pain points. A proto-persona is written from assumptions and has not yet been tested with real users.
    Provenance label
    How sure a stated fact is: V verified at the primary source, S found through search, K background knowledge, U unconfirmed.
    Read-only
    Only looks at information; never changes, adds or deletes anything. Every tool in this server is read-only.
    Recommended attribute
    An attribute xGov MEM advises but does not require. Missing ones give warnings, not errors.
    Required attribute
    An attribute a record must have to meet xGov MEM.
    Service blueprint
    A diagram of a journey in lanes: what the person does and sees (front stage), what happens behind it (back stage) and what supports it.
    Shared identifier
    A key two organisations both use for the same thing, such as a company number, VAT number, EORI number, commodity code or address reference, so their data can be joined.
    Slot
    LinkML's word for an attribute.
    Tool
    A single action an MCP server offers, such as metadata_validate.
    User journey
    The stages a person goes through to reach a goal with a service, from first need to done.
    Vaccination
    Proving a check works by breaking the thing it guards and showing that the check fails.
    xGov MEM
    The UK Cross-Government Metadata Exchange Model: the endorsed model for exchanging metadata about datasets and data services across government.
