Data discoverability · open source

Find UK public sector data and check its metadata, from your AI assistant

NDL PubSec MCP is an open-source MCP server. It lets an AI assistant search data.gov.uk and check metadata against the UK Cross-Government Metadata Exchange Model (xGov MEM).

Take the tourFind your roleTry the checkerSet it up
  • 6read-only tools
  • 32/32model test cases agreed
  • 50/50real records agreed
  • 7standards explained
  • 28defects, each with a check

Every tool is read-only. No personal data is read or returned. Results come from the sources named with them, and the assistant you use can still make mistakes, so check the source before you rely on a result.

What it does

Each tool does one job. Filter them by what you want to do.

catalogue_search

Search data.gov.uk

Search the data.gov.uk catalogue of UK public sector datasets. Returns titles, publishers, licences, formats, last-modified dates and links. Read-only; no personal data is returned.

  • Find data
  • Uses the live catalogue
  • Read-only
Inputs
  • query (required): What to look for, in plain words, for example 'school census' or 'flood risk'
  • organisation: Optional publisher slug from data.gov.uk, for example 'department-for-education'
  • limit: How many results to return (1 to 20)
  • offset: How many results to skip, for paging

dataset_describe

Describe a dataset and check it against xGov MEM

Get one data.gov.uk dataset: its description, publisher, licence and distributions, plus a draft UK Cross-Government Metadata Exchange Model (xGov MEM) record and what that record still lacks. Nothing is guessed: fields the catalogue does not hold are reported as missing.

  • Find data
  • Uses the live catalogue
  • Read-only
Inputs
  • id (required): The dataset id or name (slug) from data.gov.uk

metadata_validate

Validate metadata against xGov MEM

Check a metadata record against the UK Cross-Government Metadata Exchange Model (xGov MEM, commit d6d9a24). Classes: ContactPoint, DataService, Dataset, Distribution, Organisation. Returns errors (must fix) and warnings (recommended), each with the attribute path.

  • Check metadata
  • Works offline
  • Read-only
Inputs
  • record (required): The metadata record as a JSON object, using xGov MEM attribute names
  • className: Which xGov MEM class to validate against. If left out, it is read from the record's type, for example dcat:Dataset

standard_explain

Explain an open data standard

Explain open data standards used across UK government (xGov MEM, DCAT, ATRS, BODS, CSV, OpenAPI and others): purpose, status, licence and link, each with its provenance label and check date. Leave id out to list them all.

  • Explain
  • Works offline
  • Read-only
Inputs
  • id: Standard id, for example 'xgov-mem', 'dcat' or 'bods'. Leave out to list all

term_lookup

Look up a business term and whether it is certified

Find business terms in the configured vocabulary and report, for each, its definition, its status, who drafted it (person or AI), the review level it passed (H0 to H5) and whether that makes it certified. A term counts as certified only when it is endorsed after H2 review or above; anything unrecorded is reported as unknown, never assumed. Leave query and id out for a summary of the vocabulary.

  • Explain
  • Works offline
  • Read-only
Inputs
  • query: Words to look for in term labels, alternative labels and definitions
  • id: An exact term id, for example 'NDL-GLO-007'
  • limit: How many terms to return (1 to 25)

domain_list

List the MCP servers in this estate

List the MCP servers that work alongside this one (for example the Public Sector Data Quality Commons), with what each is for, its tools, its safety statement and where its manifest came from. This server does not call them.

  • Connect
  • Works offline
  • Read-only

How well it follows xGov MEM

The validator is generated from the xGov MEM model at commit d6d9a24 (1 June 2026). It covers 5 classes.

It reaches the same verdict as the model's own tests on 32 of 32 cases: 12 valid and 20 invalid examples.

  • Invalid examples rejected

50 real data.gov.uk records were mapped (a crosswalk) and checked by this server and by the model's own LinkML validator: 50 of 50 agree. None is valid straight from the catalogue. These are the required attributes the catalogue records lack.

The corpus is small, and some examples break more than one rule. The real-record sample is 50 records, not the whole catalogue. Agreement means the same verdict and the same missing attributes, not identical messages.

UK Cross-Government Metadata Exchange Model (xGov MEM)

A common model for describing datasets, data services and distributions so catalogues across government can exchange metadata.

Endorsed for implementation by the Data Standards Authority Steering Board · Open Government Licence v3.0

  • S: Found through search; re-verify
  • metadata_validate
  • dataset_describe

Data Catalog Vocabulary (DCAT)

W3C vocabulary for describing datasets and data services in catalogues; the base vocabulary xGov MEM builds on.

Base standard of xGov MEM · W3C

  • V: Verified at the primary source
  • metadata_validate

Algorithmic Transparency Reporting Standard (ATRS)

A standard way for public sector bodies to publish information about the algorithmic tools they use.

Endorsed · Open Government Licence v3.0

  • V: Verified at the primary source

Beneficial Ownership Data Standard (BODS) v0.2

Collect, use, exchange and publish information about who owns and controls companies and other legal entities.

Endorsed · Apache License 2.0

  • V: Verified at the primary source

Common Format and MIME Type for Comma-Separated Values (CSV) Files (RFC 4180)

The common format for publishing tabular data as CSV.

Endorsed · Not stated in the catalogue

  • V: Verified at the primary source

OpenAPI 3 (describing RESTful APIs)

A machine-readable way to describe RESTful APIs.

Recommended open standard for government · Apache License 2.0

  • V: Verified at the primary source

Getting started

Do I need to install anything to try it?

No. The record checker on this page runs the server's own validator in your browser. To use the six tools from an assistant, you need to install the server.

What do I need to install it?

Node.js 20 or later, git, and an assistant that supports MCP, such as Claude Desktop or VS Code.

Which assistants work?

Any assistant that can start an MCP server over stdio. Snippets are given for Claude Desktop and VS Code; others follow the same pattern.

Using the tools

How do I choose a tool?

You usually do not: ask your question and the assistant picks. To be sure, name the tool in your prompt, for example 'use metadata_validate'.

Can I check many records at once?

Each call checks one record. Ask the assistant to go through a list and give you a table, then check the totals yourself.

Why do I see at most 100 findings?

Findings are capped at 100 per call, with a count of how many were left out, so one very broken record cannot flood the reply (defect D-020).

Can I point it at a different catalogue or vocabulary?

Yes. NDL_MCP_CKAN_BASE sets the catalogue API (https only) and NDL_MCP_VOCAB_PATH sets the vocabulary term_lookup reads. See the README for details.

Trust and safety

Does it change anything?

No. Every tool is read-only. It never writes to a catalogue, sends messages or stores what you ask.

Does it handle personal data?

No personal data is read or returned. Do not paste personal data into the checker or your prompts.

Can I rely on the answers?

Results come from the sources named with them, but the assistant can still make mistakes. Check the source before you rely on a result, and treat provenance labels S, K and U as leads, not facts.

Is this a government service?

No. It is an independent prototype. It is not endorsed by any government department and does not set policy.

Troubleshooting

The assistant does not show the tools

Check the path in the settings points at dist/index.js, that npm run build finished, and restart the assistant. Then try npm run inspector.

Search returns nothing or fails

The catalogue may be unreachable. A weekly live smoke test watches for changes to its API; check the open items, then raise it through the contact form.

The checker says my record is invalid, but I think it is right

Check the class is right and attribute names are spelt as the model spells them (UK spelling, for example licence). If you still disagree, tell us: it may be a difference from the standard.

  • PromptingName the tool in your prompt when you need a specific one.
  • PromptingAsk for a table with the catalogue link in every row, so each answer can be checked.
  • PromptingAsk the assistant to say how sure it is, and which tool each fact came from.
  • SearchingUse organisation, limit and offset with catalogue_search to page through one publisher's records.
  • CheckingA missing attribute next to an unknown one with a similar name is usually a spelling difference.
  • CheckingValues in the model's lists are exact, including capitals: OPEN, not Open.
  • ReportingRecord the model commit shown with the results whenever you report conformance.
  • ReportingCite the catalogue entry, not the assistant.
  • PublishingKeep the validated JSON next to the change you make in your own catalogue.
  • ChampioningUse the in-page checker for live demos: it needs no network.

What has changed

Newest first. Each release links to its full entry in the changelog.

  1. Version 0.4.0

    20 November 2026 · 13 changes

    Show the changes
    • The website is rebuilt with its own design instead of GOV.UK styles, so it is not mistaken for a government service. It says plainly that this is an independent prototype, not endorsed by any government department. The README, product requirements, contact form and citation no longer name a team or a government publisher (D-024).
    • ADR 0006 supersedes the wording of ADR 0002 that described this repository as official. Copyright and licences are unchanged.
    • An in-browser metadata checker on the website. It runs the server's own validator, bundled at build time, so nothing pasted leaves the browser. A test proves the bundle agrees with the server.
    • Website: light and dark themes, a retractable contents drawer with item counts and new-section flags, filters and search for tools, standards, documents, open items, defects and the glossary, glossary tooltips, conformance charts for the model's tests and for 50 real records, an estate map, set-up tabs for Claude Desktop and VS Code with copy buttons, a release timeline and the open register.
    • Repository checks C-16 (no team name, claims of official status, GOV.UK styles or government publisher), C-17 (the independent-prototype statement on the page and README) and C-18 (unique ids and no dangling references on the page), each with a negative test (D-024, D-025).
    • The dependency on the GOV.UK front-end package, and its stylesheet.
    • The Cabinet Office vulnerability disclosure route in SECURITY.md.
    • Pre-commit hooks: detect-secrets against a new .secrets.baseline, YAML and JSON checks, whitespace fixes, and gitlint for GDS Way commit messages (.gitlint).
    • .secrets.baseline with every candidate audited, and the audit recorded in docs/compliance/secrets-audit.md.
    • codeql.yml sets read-only permissions at the top level; the analyze job keeps the permissions it needs.
    • The parity tools pair results with zip(..., strict=True), so a length mismatch fails instead of passing silently (D-023).
    • CI lints the Python tools with Ruff and fails on any finding; repository check C-15 keeps it there (D-023). Part of applying the secure development standard to every project.
    • Re-vendored the Data Quality Commons manifest at dq-commons@76386f8: domain_list now reports all 15 of its tools (closes O-16; D-021 resolved upstream in dq-commons#41).

  2. Version 0.3.0

    11 November 2026 · 6 changes

    Show the changes
    • term_lookup: business terms with their certification state (status, drafted by a person or AI, review level H0 to H5). Certified only when endorsed after H2 or above (ADR 0005).
    • domain_list and the ndl-pubsec-mcp://federation resource: the other MCP servers in the estate, starting with the Data Quality Commons (dqkit), with provenance.
    • integrations/ndl-mcp-domain.json: this server's own manifest, in the same shape as dq-commons'.
    • tools/build-vocab.mjs: generates the public example vocabulary from docs/glossary.md.
    • Checks C-12 (vocabulary generated, claims no review) and C-13 (manifests match the registered tools; vendored manifests carry provenance), each with deliberate-break tests.
    • D-021: the estate's two MCP servers did not reference each other, and the dq-commons manifest listed 12 of its 15 tools.

  3. Version 0.2.0

    8 November 2026 · 15 changes

    Show the changes
    • MCP server with four read-only tools: catalogue_search, dataset_describe, metadata_validate and standard_explain, plus two resources.
    • An xGov MEM validator compiled from the upstream LinkML model at commit d6d9a24. It agrees with all 32 cases in the upstream test corpus.
    • A data.gov.uk to xGov MEM crosswalk that drafts only what the catalogue holds.
    • Tests (unit, protocol end-to-end, and a deliberate-break test for every repository check), CI, Pages, Dependabot and CODEOWNERS.
    • The usual document set at G3: PRD, architecture, data dictionary, glossary, knowledge graph, ADRs, governance screening, and defect, open and case-against registers.
    • A contact issue form, and private vulnerability reporting in place of an email address.
    • tools/linkml_parity.py: 45 varied records give the same verdict here as in linkml-validate 1.12.1; runs in CI (O-02).
    • tools/live_parity.py: 50 real data.gov.uk records, crosswalked, get the same verdict and missing attributes in both; repeated weekly (O-05).
    • Standards register re-read at primary pages: five entries are now verified (O-04).
    • A bare value for a list is now an error, as in LinkML (D-019).
    • metadata_validate returns at most 100 findings, with exact counts and an omitted total, so a hostile record cannot inflate the reply (D-020).
    • Flattened the layout: the nested ndl-pubsec-mcp/ folder is gone.
    • Licence holder corrected to Crown copyright (Government Digital Service). The earlier "as a DSIT officer" and personal-project statements contradicted each other (defect D-007).
    • The six citizen-domain scopes, theory of change, user research bundle and portfolio pages. They moved to the owner's separate personal experiment repository and remain in this repository's history before 0.2.0.
    • The broken CI workflow (no .yml extension, so it never ran) and the Jekyll Pages workflow that published the wrong folder.

CKAN
The open-source catalogue software behind data.gov.uk. Its "action API" is what this server calls.
Class
A kind of thing in xGov MEM, for example Dataset or DataService.
Co-design
Designing a service with the people who will use it, not only for them: they shape the personas, journeys and changes.
Crosswalk
A mapping from one metadata format to another; here, from a data.gov.uk entry to xGov MEM.
CURIE
A short form of a web address, written prefix:name. For example, dcat:Dataset.
DAM policy
The cross-government policy on critical data assets (the successor to the Essential Shared Data Asset policy), with returns to GDS from January 2027.
Data champion
Someone who promotes good data practice in their own organisation, often alongside their main job.
data.gov.uk
The UK's national catalogue of public sector data.
DCAT
Data Catalog Vocabulary, the W3C standard for describing datasets in catalogues. xGov MEM builds on it.
Distribution
One available form of a dataset, such as a CSV file or an API.
Finding
One problem the validator reports, with a severity, a path and a message.
LinkML
The modelling language xGov MEM is written in.
MCP
Model Context Protocol: an open standard for connecting AI assistants to tools and data.
MCP server
A program that offers tools and resources to an AI assistant using MCP. This repository is one.
Persona
A short description of a type of user: their context, goals and pain points. A proto-persona is written from assumptions and has not yet been tested with real users.
Provenance label
How sure a stated fact is: V verified at the primary source, S found through search, K background knowledge, U unconfirmed.
Recommended attribute
An attribute xGov MEM advises but does not require. Missing ones give warnings, not errors.
Required attribute
An attribute a record must have to meet xGov MEM.
Service blueprint
A diagram of a journey in lanes: what the person does and sees (front stage), what happens behind it (back stage) and what supports it.
Slot
LinkML's word for an attribute.
Tool
A single action an MCP server offers, such as metadata_validate.
User journey
The stages a person goes through to reach a goal with a service, from first need to done.
Vaccination
Proving a check works by breaking the thing it guards and showing that the check fails.
xGov MEM
The UK Cross-Government Metadata Exchange Model: the endorsed model for exchanging metadata about datasets and data services across government.

Accessibility statement

I want as many people as possible to be able to use this page. It aims to meet the Web Content Accessibility Guidelines (WCAG) 2.2 at level AA. It works without JavaScript, follows your light or dark setting, and stops motion when you ask your device to reduce it. It has been checked with automated tools only, and manual testing with assistive technology has not been done yet, so it does not claim full compliance. If you find a problem, or need this information in another format, use the contact form. If you cannot use the form, ask someone to raise it for you.
